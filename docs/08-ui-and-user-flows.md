# 可视化工作台与交互设计

## 目标

让客服、主管和仓库人员在一个工作台中完成查询、草稿确认、审批和结果追踪。任何写操作都展示具体业务对象、数量或金额以及执行状态。

## 页面结构

| 页面 | 路由 | 内容 |
|---|---|---|
| 登录 | /login | 商家编码、用户名、密码 |
| 对话工作台 | /workspace | 会话列表、聊天、业务信息与引用 |
| 工单列表 | /tickets | 状态、类别、订单筛选 |
| 工单详情 | /tickets/:id | 内容、处理事件、关联申请 |
| 库存 | /inventory | SKU 各仓库存、建议与调拨单 |
| 审批 | /approvals | 待处理与历史申请 |
| 知识库 | /knowledge | 上传、处理、版本预览、发布 |
| 审计 | /audit | 按 traceId 和业务对象过滤 |

知识库和审计按权限展示；前端隐藏入口只是交互提示，权限由后端校验。

## 对话工作台

桌面布局为左侧会话列表、中间对话、右侧业务详情。移动或窄屏时右侧以抽屉展示。默认不做首页数据大屏，优先展示实际业务操作。

消息内容包括：用户问题、查询进度、事实摘要、政策答复、引用编号和操作卡片。引用点击后显示标题、版本、日期、页码/章节及引用文字。

工具进度仅显示名称、完成情况、耗时和脱敏摘要。系统提示词、内部推理和原始模型报文不作为产品内容展示。

草稿卡片展示：

- 工单：类别、标题、订单号、问题摘要、优先级，按钮“确认创建工单”。
- 退款：订单号、申请金额、理由、政策依据，按钮“提交退款审批”。
- 调拨：源仓、目标仓、SKU、数量、估算运输时间和成本，按钮“提交调拨审批”。

卡片明确“提交申请后仍需审批”。修改内容通过生成新草稿完成，旧卡片显示失效；不能用前端改字段绕过服务器校验。

## 一条完整交互

1. 客服登录，输入演示订单号和问题。
2. 界面展示订单查询、物流判断、政策检索的实际进度。
3. 展示答复和引用，右侧打开订单详情。
4. 客服确认工单卡片，按钮进入加载状态并发送固定幂等 Key。
5. 成功后卡片展示工单号与详情入口；网络重试仍复用同一个 Key。客服领取工单并点击“开始处理”，状态转 IN_PROGRESS。
6. 客服以已创建的工单号继续会话，生成关联退款草稿；确认卡片后得到 PENDING_APPROVAL 申请，工单转 WAITING_APPROVAL。
7. 主管账号登录，在审批页查看参数、理由、引用与申请人。
8. 主管批准，先显示 APPROVED，随后轮询显示 SIMULATED_SUCCEEDED。
9. 客服打开工单时间线，看到审批及模拟执行结果。

## 库存与审批页面

库存表区分实存、预留、可用和可调配数量，显示计算时间。建议表注明源仓和单源仓方案限制，不把候选数量误当成已经预留。

审批详情展示保存的申请参数、申请人、创建时间、截止时间、政策或库存依据。审批人员不能修改业务参数，只能批准或拒绝并填写理由。自己的申请不显示可审批按钮，并保留原因提示。

APPROVED 与执行成功分别显示；FAILED、REJECTED、EXPIRED 有明确原因。库存变化导致失败时提供“重新生成建议”入口，不将失败卡片恢复成待审批。

## 知识库页面

上传后展示 UPLOADED → PROCESSING → READY；READY 可预览抽取文本、片段定位和生效日期，再手动发布。

FAILED 提供文件格式、空文本或向量调用错误说明。扫描 PDF 提示首期不支持 OCR。历史版本可查看，停用版本不进入新的政策答复。

## 错误与重连

SSE 使用 fetch + Authorization，记录 runId 与最后 sequence。短暂断线后重连回放，重复序号不重复插入消息；令牌过期先重新登录，再读取最终运行结果。

答案失败时保存已经完成的查询，展示错误原因和重试按钮，并提供“手工创建工单”表单，经手工草稿接口及确认接口创建。点击取消停止后续 Agent 查询，不删除已创建的工单或申请。

重复点击确认由后端幂等控制；前端按钮禁用只是减少误操作。409 版本冲突刷新资源，410 草稿过期提示重新生成。

## 可访问性与交互质量

表单字段有标签，错误文字可定位，状态同时使用颜色与文本。对话区域可键盘访问，引用和确认按钮有明确名称。支持减少动态效果，避免使用快速闪烁指示。

首期采用统一状态文案，显示金额时按分转元并保留两位小数。所有模拟退款结果明确标记“模拟执行”，库存预留明确标记“等待发运”。

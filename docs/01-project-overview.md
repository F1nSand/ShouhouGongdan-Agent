# 项目简介

## 项目名称

智能售后工单与库存调度 Agent，英文标识 Aftersales Agent。

## 项目背景

面向具有多个仓库的中小型电商商家。客服处理订单未送达、物流长时间未更新、退换货申请和缺货咨询时，需要反复切换订单、物流、政策文档和库存页面，再手工整理工单并联系仓库人员。

业务数据分散使得答复依据不统一，问题描述和工单内容重复录入，敏感处理缺少完整追踪。项目通过自然语言入口把查询、政策解释、工单和审批串联起来，使客服能够看到每一步使用的业务信息与政策依据。

上述问题是项目业务设定，不代表已经采集了真实企业的成本或效率数据。演示数据使用合成订单、库存和模拟物流事件。

## 项目目标

构建基于 Java 后端的售后助手，接收自然语言问题，通过受控工具访问业务信息，检索适用的售后政策，生成可确认的工单或敏感操作草稿。库存调度建议由确定性规则计算，Agent 负责解释建议和组织业务流程。

项目同时提供客服与仓库可视化工作台，展示引用依据、工单进度、审批结果和操作轨迹。

## 目标用户

| 用户 | 工作与价值 |
|---|---|
| 客服人员 | 查询订单、解释政策、创建工单、提交处理申请 |
| 客服主管 | 审批退款申请，处理升级工单 |
| 仓库运营人员 | 查询库存、审阅调拨建议、审批库存预留 |
| 商家管理员 | 管理账号、发布政策知识、查看审计 |
| 消费者 | 后续通过自助入口查询本人订单与工单 |

首期主要交付内部工作台，消费者自助入口作为第二阶段扩展。

## 核心业务流程

1. 客服输入“订单 AF20260926001 一直没收到，用户想退款”。
2. 后端确定身份与商家范围，Agent 查询订单、最新物流事件。
3. 规则服务判断物流是否异常，检索订单购买时适用的售后政策。
4. 系统展示事实、政策引用和下一步建议。订单信息不足时先询问订单号。
5. Agent 整理工单草稿；客服确认后创建工单。
6. 如需退款或库存调拨，确认草稿后生成待审批申请。
7. 客服主管或仓库运营人员审批；执行器再次校验订单或库存状态。
8. 首期退款执行模拟适配器，调拨执行本地调拨单创建与库存预留。
9. 所有记录关联会话、工单、申请和 traceId，支持查询与回放。

## 首期实现范围

| 功能 | 交付内容 |
|---|---|
| 订单与物流查询 | 按订单号查询、脱敏展示、物流事件与异常原因 |
| 售后政策问答 | PDF/Markdown/TXT 导入、向量检索、有效期过滤、引用展示 |
| 工单处理 | 草稿、确认创建、查询、分派、状态流转 |
| 库存与调拨建议 | 多仓库存查询、可调配量、时间与成本排序、建议解释 |
| 审批与审计 | 退款/调拨申请、角色审批、执行状态、审计轨迹 |

首期不交付真实支付退款、实物仓储出入库、实时物流平台接入、复杂运筹优化或跨商家交易。订单与物流通过演示适配器提供，接口边界支持后续替换。

## Agent 的操作边界

| 处理方式 | 操作 |
|---|---|
| 自动执行 | 身份范围内的订单、物流和库存查询；政策检索；异常识别；草稿生成 |
| 仅提供建议 | 退款适用性、物流处理方案、跨仓调拨方案、工单优先级建议 |
| 用户确认后执行 | 创建工单；提交退款或库存调拨审批申请 |
| 必须角色审批 | 模拟退款执行；调拨单创建及库存预留 |

草稿确认用于确认用户意图；审批用于决定敏感操作是否可以执行。模型无法代替用户确认或审批人员决定。

## 技术方案

Java 21、Spring Boot、Spring AI、Spring AI Alibaba Agent Framework；PostgreSQL 保存业务和操作数据，pgvector 保存政策向量；Redis 用于查询缓存与限流；Spring Security 管理身份权限；Flyway 管理迁移；Vue 3 + TypeScript 提供工作台；Docker Compose 管理本地应用与基础服务。

## 验证指标

计划测量工具调用成功率、政策回答引用率、政策检索命中率、工单创建成功率、审批越权阻止率、并发库存一致性、首段响应与总响应时间。指标定义和验收目标见 [测试与评估](09-testing-and-evaluation.md)，项目完成后填写实测值。

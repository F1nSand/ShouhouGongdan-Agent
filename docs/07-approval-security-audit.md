# 操作确认、审批、安全与审计

## 三个独立阶段

操作草稿整理业务参数；用户确认表达处理意图；敏感操作审批授权实际执行。确认工单可以直接创建工单，确认退款或库存调拨只能创建待审批申请。

~~~mermaid
sequenceDiagram
    participant U as 客服
    participant A as Agent
    participant C as 确认服务
    participant H as 审批人员
    participant E as 执行器
    participant DB as 数据库
    U->>A: 描述售后问题
    A->>DB: 保存不可变草稿
    A-->>U: 展示依据与操作参数
    U->>C: 确认 draftId + 幂等 Key
    C->>DB: 待审批申请与确认审计
    H->>C: 审批 actionId + expectedVersion
    C->>DB: 审批决定 + outbox
    E->>DB: 领取任务并复核状态
    E->>DB: 本地库存事务或模拟退款结果
    E-->>U: 可查询的执行结果
~~~

## 权限矩阵

| 操作 | 客服 | 主管 | 仓库 | 管理员 |
|---|---|---|---|---|
| 查询商家订单、政策 | 是 | 是 | 脱敏业务字段 | 是 |
| 查询库存、获取建议 | 是 | 是 | 是 | 是 |
| 创建/确认工单草稿 | 是 | 是 | 否 | 是 |
| 提交退款申请 | 是 | 是 | 否 | 是 |
| 提交调拨申请 | 是 | 是 | 是 | 是 |
| 审批退款 | 否 | 是 | 否 | 是 |
| 审批调拨 | 否 | 否 | 是 | 是 |
| 发布与停用政策 | 否 | 否 | 否 | 是 |
| 查看全商家审计 | 否 | 审批关联记录 | 否 | 是 |

角色枚举：CUSTOMER_SERVICE、SERVICE_SUPERVISOR、WAREHOUSE_OPERATOR、ADMIN。消费者角色暂不开放。所有审批人员都不能批准本人提交的申请。

订单对象权限和商家过滤同样应用于嵌套工具、草稿、引用、审批、下载与 SSE。其他商家资源统一返回 404，避免泄露存在性。

## 登录与身份

账号通过商家编码、用户名和密码登录。商家编码用于定位账号所属范围，不接受登录后的 tenantId 覆盖。密码采用 BCrypt，失败信息不区分用户名和密码是否正确。

访问令牌有效期 30 分钟，包含签发方、用户、角色、商家和过期时间；服务端校验签名与账号状态。演示环境预置两个不同人员账号用于提交和审批，初始密码由种子配置注入。

线上部署采用 HTTPS，前端令牌保存在内存中，刷新页面重新登录；首期不做长期刷新令牌。日志、URL 与浏览器持久存储不保存模型 Key 或访问令牌。

## 草稿确认

草稿包含不可修改的 payload、payloadHash、evidenceSnapshot、createdBy、expiresAt。客户端只提交 draftId，服务器再次读取草稿，不接受确认请求覆盖金额、SKU、数量、仓库或政策依据。

草稿有效期 30 分钟。确认先锁定草稿并检查商家、创建者、角色、READY 状态和有效时间；成功后同事务创建唯一工单/申请、保存确认结果、标记 CONFIRMED、写审计。

已确认的草稿再次确认返回原始结果。PREPARING 草稿不允许确认；INVALIDATED 或 EXPIRED 草稿不能重新启用，修改参数时创建新草稿。

批准人员读取申请保存的 evidenceSnapshot，不需要读取申请人私有对话。快照用于解释当时建议，执行仍重新校验当前订单与库存事实。

## 审批

申请默认 24 小时过期。决定必须基于已保存 payloadHash 与 expectedVersion；审批时检查角色、自批禁止、PENDING_APPROVAL、金额/库存事实和有效期。

APPROVE 只把状态改为 APPROVED 并生成 outbox。REJECT 保存理由并转 REJECTED。重复相同幂等命令返回原始决定，第二个新的决定请求不能覆盖第一个决定。

超过期限且尚未开始执行的 PENDING_APPROVAL/APPROVED 申请转 EXPIRED。EXECUTING 申请由执行恢复逻辑接管，不做无条件超时作废。

## 执行与恢复

执行器以短事务领取 READY 或租约过期任务，设置 60 秒 lease，持续执行时每 15 秒续租；使用 actionId 作为业务效果级幂等标识。多执行器竞争通过行锁和状态条件更新保护。

领取时更新 lease_owner 与递增 lease_version，续租和完成任务须匹配领取版本。旧执行器失去租约后不能覆盖新任务状态；库存业务事务仍通过申请状态、唯一 actionId 和原子更新限制效果。

领任务与调用模型无关联，执行器只接受已批准、payloadHash 匹配的申请。调用远程适配器时不持有数据库锁。

首期执行：

- REFUND_REQUEST：读取订单并校验申请金额 > 0 且不超过已付金额减去已退款金额。模拟适配器返回带 simulation=true 的结果，状态 SIMULATED_SUCCEEDED；不调用支付接口、不修改真实退款总额。
- STOCK_TRANSFER：重新校验 SKU、两个仓库、路线与当前可调配量；同事务预留、创建调拨单/预留记录、设置 SUCCEEDED、写审计。

任务失败：可重试基础故障最多三次，间隔 1 秒、5 秒、30 秒；业务条件失败不重试。库存事务回滚不产生部分效果。重启后领取过期租约，通过唯一 actionId 检查已有结果，再决定完成还是重试。

后续真实支付适配器必须支持幂等请求、外部状态查询和结果对账。发生“请求发出但本地未记录结果”的不确定状态时先查询支付状态，不能直接重复退款。首期不声称具有真实资金级幂等。

## 审计

审计事件至少包含事件 ID、商家、操作者、角色、traceId、资源 ID、动作、结果、参数摘要、时间和失败原因。

成功写操作审计与业务更新同事务；权限拒绝、校验失败和事务回滚的记录由独立审计事务写入，避免失败后记录消失。参数摘要保存脱敏后的必要业务字段及 payloadHash。

应用数据库账号无 audit_events 更新和删除权限。此措施提供追加性约束，不宣称数据库管理员也无法篡改；更强的签名日志和异地备份属于后续增强。

## 风险控制

- DB 中的订单、库存与审批状态是事实源，Redis 或模型生成内容不能决定可执行性。
- 模型可见工具仅限查询和草稿生成，不能注册批准、支付或任意数据库写入工具。
- 文件上传校验真实类型、大小和路径，使用随机存储名称，禁止路径穿越。
- Redis 限流键带商家与用户；默认每人每分钟 10 次 Agent 请求，同会话一个活跃运行。
- API Key 通过环境或密钥管理服务注入，公开仓库和演示截图不包含真实密钥。

## 数据保留

会话正文、运行事件和模型输入摘要默认保留 30 天；存在工单或申请关联时，会话和运行的标识元数据继续保留。审计默认 180 天；命令去重至少 90 天。已发布政策与业务对象有关的引用快照保留到业务记录归档后。

清理作业必须检查引用关系；清理会话事件后最终答复仍按业务归档策略保留，不能让现存工单中的证据链接失效。演示数据只含合成身份，不采集真实个人资料。

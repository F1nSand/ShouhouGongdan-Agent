# 演示、展示材料与简历表达

## 项目定位

展示一个围绕售后业务独立设计的 Java Agent 系统，重点是自然语言工具调用、政策证据、业务事务、人工审批和可追踪的操作。技术说明按采用的框架及实际工程实现展开。

后端业务、Agent 会话和 Vue 工作台已交付 Docker Desktop 本地演示栈。2026-10-01 实测真实订单查询、工单草稿、政策引用、客服确认与主管退款审批；退款记录进入合成订单的本地账本，不调用支付网关。完整 mock 评估为 108/140 通过、32 项失败、20 项审批 fixture 未执行；这不是模型效果指标。详细范围和失败分类见[本机验收报告](reports/2026-10-01-acceptance.md)。

## 七分钟演示脚本

| 时间 | 演示 | 应看到的证据 |
|---|---|---|
| 0:00–0:45 | 介绍场景与架构 | 工作台、Java 后端、业务数据库、政策检索 |
| 0:45–2:00 | 客服查询延迟订单 | 订单事实、物流异常码；政策样例需事先上传并发布 |
| 2:00–3:00 | 确认工单草稿并重复点击 | 一个工单号、确认记录、重复提交无新工单 |
| 3:00–4:15 | 提交退款申请，主管审批 | 申请人和审批人不同；合成订单退款账本有入账记录 |
| 4:15–5:30 | 查询库存、建议并审批调拨 | 源仓排序依据、预留前后数量、调拨单 |
| 5:30–6:15 | 展示异常或拒绝 | 自批拒绝、过期草稿或库存变化失败 |
| 6:15–7:00 | 展示审计与评测 | traceId 轨迹、自动化验证报告、尚未测量的指标边界 |

工作台地址为 http://127.0.0.1:38080。演示订单、物流、商品、退款与政策都是合成数据。管理员首次通过 `scripts/init-demo.ps1` 上传并发布三份政策；该初始化会调用 Qwen embedding，日常启动不重复调用。客服/主管账号密码只保存在本地 `.env`。退款审批真实更新本地订单累计退款额并写幂等退款账本；不接支付接口。库存审批只对源仓库存做本地预留，不代表运输和目标仓收货。

## 当前可以使用的项目简介

可用于尚未开发完成时的说明：

“面向电商客服与仓库协作场景，构建基于 Java、Spring Boot 和 Spring AI Alibaba 的售后助手。实现订单物流查询、政策检索引用、工单草稿确认、退款与调拨审批流程、库存建议和 Vue 工作台；通过 PostgreSQL/pgvector、租户隔离、幂等事务及审计记录管理业务边界。退款为模拟执行，调拨仅进行本地库存预留。真实后端浏览器流程、故障恢复和 4 核/8 GB 限额下的本机订单查询基线已有验收记录；真模型 20 条评测及 planner 修正后的全量回归待完成。”

## 完成后使用的项目简介

仅在对应功能已经实现、测试通过并有材料后使用：

“面向电商客服与仓库运营，构建基于 Java 与 Spring AI Alibaba 的售后智能助手，支持自然语言订单和物流查询、带政策引用的问答、工单创建及库存调拨建议。采用 PostgreSQL + pgvector 管理业务数据与政策证据，通过用户确认、角色审批、幂等执行和审计记录控制敏感操作，提供 Vue 可视化工作台。”

其中退款使用模拟适配器、调拨只做库存预留时，在项目介绍或演示说明中明确这一范围。

## 可以形成的简历技术要点

- 设计受控 Agent 工具层，将自然语言查询与订单、物流、库存服务连接，业务权限与数据范围由后端校验。
- 建设带版本、生效时间与定位信息的政策 RAG，实现检索证据校验和回答引用。
- 实现草稿确认、角色审批、outbox 执行和 actionId 幂等，追踪申请与执行状态。
- 通过数据库原子更新和事务实现库存预留，使用并发测试验证库存约束。
- 建设 REST/SSE 工作台，展示业务事实、引用、工具进度和审计轨迹。

只保留实际实现并验证的部分。未交付的真实支付、真实仓储系统对接、多仓优化或多 Agent 协作不写成项目功能。当前评测语料的条数不是模型效果指标；不得据此声称回答准确率、延迟或成本收益。

## 指标使用规则

用“在 120 条业务评测和明确测试环境下测得……”说明范围，附真实模型或 mock 区别。成功率保留分子和分母，性能附并发、机器配置及 P95。

不得将设计目标、最佳单次结果或固定 mock 输出写成实际模型效果；不得声称未经验证的用户规模、商业成本下降或生产交易量。

指标实测后写入 docs/reports/，再根据报告修改简历。设计阶段不预填百分比与吞吐量。

## 面试讲解问题

1. 为什么选择模块化单体，何时才拆分服务？
2. Agent 何时查工具、何时提问、何时转人工？
3. 如何保证政策适用于订单购买时间？
4. 为什么工单创建和库存预留不能直接相信模型输出？
5. 草稿确认、敏感审批和执行成功有什么区别？
6. 请求重复、服务重启、任务重复领取如何保证业务效果？
7. 并发库存预留为什么不用缓存数量作为依据？
8. 工具调用、知识命中、引用和延迟指标如何统计？
9. 当前模拟适配器与真实业务接入的差距是什么？

每个回答都对应文档、代码和测试证据，避免只讲框架名称。

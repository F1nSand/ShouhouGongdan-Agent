# 产品需求与验收标准

版本：v1.0。状态：设计完成，等待开发。所有时间计算使用服务端 UTC，工作台按用户时区显示。

## 业务假设

- 一个商家具有多个仓库，每个 SKU 的库存按仓库单独记录。
- 订单、物流和政策是独立事实源，模型不能生成不存在的订单或库存数量。
- 客服可处理本商家订单；消费者入口上线后只能访问本人订单。
- 退款展示限定于模拟执行；库存操作限定于预留，不执行实物出入库。
- 政策适用日期默认取订单购买时间，普通政策问答取当前时间。

## 角色与需求

| 编号 | 用户故事 | 验收 |
|---|---|---|
| US-01 | 客服输入订单号后了解订单和物流情况 | 返回订单状态、金额、物流更新时间和来源；不存在时明确说明 |
| US-02 | 客服了解订单适用的退款政策 | 回答带有效政策版本、片段与定位；无依据时不编造结论 |
| US-03 | 客服将会话整理为工单 | 草稿可查看；确认后持久化；重复确认得到同一工单 |
| US-04 | 仓库人员寻找可调拨库存 | 输出源仓、目标仓、SKU、数量、预计运输时间和成本依据 |
| US-05 | 主管审批退款或仓库人员审批调拨 | 申请人不能自批；过期或状态变化时拒绝执行并给出原因 |
| US-06 | 管理员追踪操作过程 | 可按 traceId、工单和申请查看身份、时间、参数摘要和执行结果 |
| US-07 | 管理员更新政策 | 文档先处理、预览再发布；新版本发布后旧版本保留历史引用 |

## 功能要求

### F-01 订单与物流

按商家内订单号精确查询，不按模型猜测的姓名或电话号码模糊取单。订单详情包含订单号、购买时间、状态、脱敏消费者标识、商品、金额与物流事件。

物流异常规则：

- 已发货且最后物流事件距当前时间超过 48 小时：NO_UPDATE。
- 承运状态为 EXCEPTION：CARRIER_EXCEPTION。
- 超过订单承诺送达时间且未签收：OVERDUE。
- 无物流事件：以订单 shipped_at 为计时起点，超过 48 小时判 NO_UPDATE，未超过则仅展示等待信息。缺 shipped_at 时提示数据不足。

规则采用演示业务参数，可在配置中调整。一次订单可以有多个异常原因；已签收或取消订单不继续按无更新判断。物流阈值以服务端固定时钟测试。

### F-02 政策问答

支持文本 PDF、Markdown、TXT，单文件不超过 10 MB，PDF 不超过 200 页。扫描 PDF、密码保护文件和无法提取有效文字的文件提示处理失败，首期不做 OCR。

检索必须过滤商家、发布状态、适用类别和有效时间。答案引用只能来自本轮实际检索到的片段。政策内容冲突、证据不足或缺少关键订单事实时，提示补充信息或转人工处理。

### F-03 工单

工单类别：LOGISTICS_DELAY、REFUND、RETURN、STOCK_INQUIRY、OTHER。

Agent 提取标题、问题描述、订单关联、政策依据和建议优先级，保存为不可修改的草稿。客服需要修改时创建替代草稿，旧草稿标记失效；确认操作仅接受草稿 ID。

模型不可用时，客服通过手工表单创建 CREATE_TICKET 草稿，同样校验订单与身份、确认后创建工单；该路径不要求存在 Agent 运行，不绕过审计或幂等。

确认创建工单后返回工单号、状态和追踪入口。一个草稿最多创建一个工单，同一订单可以因不同事件产生多个工单，不使用订单号作为全局去重条件。

工单状态与变更规则见 [数据模型](04-domain-and-data-model.md)。解决工单必须写处理摘要。

### F-04 库存与调度

库存展示：

- 可用库存 = 实存数量 − 已预留数量。
- 可调配库存 = max(可用库存 − 安全库存, 0)。

建议选择同商家、同 SKU、不同于目标仓、可调配库存足够的源仓。候选按预计运输天数升序、每件运输成本升序、仓库 ID 升序排序，最多返回三个方案。

首期仅提供单源仓满足全部数量的方案；多个仓库合并供货放在后续阶段。无源仓满足条件时明确说明原因，不生成虚假方案。

建议必须保存库存版本和计算时间。审批和执行时重新查询库存；发生变化时按当前事实校验，数量不足则执行失败，不沿用旧快照。

### F-05 确认、审批与执行

草稿类型：CREATE_TICKET、REQUEST_REFUND、REQUEST_STOCK_TRANSFER。

客服确认工单草稿后立即创建工单。确认另外两类草稿只生成 PENDING_APPROVAL 申请：

- 退款：由客服主管或管理员审批，模拟执行，标记 SIMULATED_SUCCEEDED。
- 调拨：由仓库运营或管理员审批，创建调拨单并预留源仓库存，标记 SUCCEEDED。

申请人禁止审批自己的申请，管理员也遵守此规则。拒绝和失败原因必须可查看。审批通过不代表执行成功，界面展示两个独立时间点。

### F-06 可視化工作台

包括对话、工单、订单详情、库存建议、审批、知识库和审计页面。对话支持流式答复、引用展开、工具结果摘要与操作确认卡片。

工具结果摘要不展示完整身份证明、收件地址、访问令牌或模型内部推理。界面详见 [交互设计](08-ui-and-user-flows.md)。

## 非功能要求

| 要求 | 首期验收标准 |
|---|---|
| 数据隔离 | 接口、工具、检索和 SSE 回放都校验商家与对象权限 |
| 幂等 | 相同草稿和相同命令重复提交只产生一次业务效果 |
| 库存一致性 | 并发预留后 reserved ≤ on_hand，且不侵占安全库存 |
| 可恢复 | 已审批写操作通过持久化 outbox 恢复；不重复预留 |
| Agent 限制 | 单轮最多 6 次模型调用、8 次工具调用、60 秒期限 |
| 可追踪 | 每个运行和写操作携带 traceId；失败仍保存摘要 |
| 测试复现 | 默认 mock profile，固定时钟和模型输出，不依赖实时付费 API |

模型质量和延迟的数字目标见测试文档，不能据此声称已经达到。
